## 📖 Description
This repository contains the infrastructure and source code for the project's firmware. The entire compilation, testing, and binary generation environment is **dockerized**, ensuring that all developers use the exact same toolchains and compiler versions.

### 🛠️ Tech Stack
* **Languages:** C / C++
* **Build System:** CMake + Ninja
* **Testing:** GoogleTest (GTest)
* **Hardware Target:** STM32 Family (Default: `stm32f103c8t6`)

---

## 🐳 Quick Start Guide (Docker Workflow)

### 1. Build the Image
Before starting, ensure you are in the root directory containing `docker-compose.yml`.

```bash
docker-compose build
```

### 2. Run Tests & Compilation (Host)
This command spins up the container, builds the project, and runs unit tests in the simulated environment.

Usage: Daily development, logic testing.

Manual command:

``` bash
 docker-compose run --rm builder bash scripts/start_testing.bash
 ```

### 3. Change Chip Model (Target)
You can inject the CHIP variable to dynamically change the build configuration.

``` bash
 docker-compose run --rm builder bash scripts/start_building.bash stm32f103c8t6
```

### 4. Generate MCU Binary (Cross-Compilation)
To generate the .elf, .bin, or .hex files for the microcontroller, we use the ARM toolchain inside Docker.

``` bash
 docker-compose run --rm builder bash scripts/start_testing.bash stm32f103c8t6 ../cmake-toolchain/arm-toolchain.cmake
```

## ⚡  Scripts Summary
To simplify the workflow, we use predefined scripts located in the /scripts folder.

| Action | Command | Description |
| :--- | :--- | :--- |
| **Run Tests** | `docker-compose run --rm builder bash scripts/start_testing.bash` | ERuns tests with default config. |
| **Compíle MCU** | `docker-compose run --rm builder bash scripts/start_building.bash stm32f103c8t6` | Compiles firmware for the specified chip. |
| **Tests + Chip** | `docker-compose run --rm builder bash scripts/start_testing.bash stm32f103c8t6` | Runs tests simulating the specific chip. |

## 🆕 How to Add a New Chip (Scaling)

If you need to work with a different microcontroller model, follow these steps to seamlessly integrate it into the build system:

1.  **Generate Base Project:** Create your STM32 project (using STM32CubeMX or STM32CubeIDE) ensuring you select **CMake** as the "Toolchain/IDE Project Structure".
2.  **Folder Structure:** Create a new folder in the project root strictly following this naming convention:
    `firmware_<chip_name>` (Example: `firmware_stm32f401ccu6`).
3.  **CMake Configuration:**
    * Navigate to the `templates/` folder in this repository.
    * Review the `CMakeList_template_firmware.txt` file.
    * Use this file as the template for your new chip's `CMakeLists.txt`. This is critical to ensure compatibility with Docker environment variables and build paths.
